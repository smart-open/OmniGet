## 二期（0.9.x）音乐纵深 — 约 4–6 周

> **主题：把独门音乐线做厚。** 第四轮核验：musicdl / go-music-dl / Audiovault 等聚合带 2026 年仍活跃，但「五平台聚合 + 原唱校验 + 试听」仍是独有能力，纵深投入方向正确。
> **进度（2026-10-04）**：五项全部落地（0.9.0，139 单测）——无损档文件头嗅探、网易云歌单/专辑批量、双语 LRC、音乐库视图、artist/album 归档模板；详见 CHANGELOG 0.9.0。遗留：歌单批量暂仅网易云（其余平台无稳定公开歌单 API，待核验后扩展）；五平台真机回归仍挂 1.2。

- [x] ✅（2026-10-04）无损音质档位：下载产物按文件头嗅探对齐真实容器扩展名（flac/m4a 等，不再硬编码 .mp3）；酷狗音质参数接线；skip_existing 多扩展名扫描
- [x] ✅（2026-10-04）歌单/专辑页批量下载：网易云歌单/专辑 URL → 公开 API 解析曲目 → 勾选 → 逐曲 ID 精确入队（复用并发闸门 ≤4）；其余平台暂缓（无稳定公开歌单 API）
- [x] ✅（2026-10-04）歌词增强：网易云 tlyric 翻译轨按时间戳合并双语 LRC（music.lyrics 设置，默认原文）
- [x] ✅（2026-10-04）「音乐库」视图：DB v3 music_tracks 完成即登记；按歌手/专辑分组 + 检索 + 本地试听 + MusicBrainz 一键补标签（#29 串成入口，原地回写）
- [x] ✅（2026-10-04）媒体服务器友好归档：`music.template` 独立键 + {{album}} 变量 + artist/album 目录结构（逐段清洗防穿越）；设置页 Navidrome 归档预设

## 六期（1.1+）可持续演进带 — 观察与评估

> **主题：不做具体承诺，维护一条经过论证的演进选项池。** 每项均有明确触发条件，条件不兑现不动工。

- [ ] 🟡 引擎韧性：aria2 上游停更风险对冲——Motrix-Next 采用维护分叉 Aria2 Next 的路线观察（四轮核验）；如原 aria2 出现不可修的安全/兼容问题，评估切换维护分叉
- [ ] 🟡 ED2K 协议支持评估：需求已被 Motrix-Next 原生 ED2K 验证；**依赖上项结论**（aria2 原生不支持，分叉支持）
- [ ] 🟡 直播录制增强（backlog #20 边界）：`--live-pipe-mux` 实时混流 + 定时分段
- [ ] 🟡 多源聚合自动化（backlog #12）：CDN 指纹表自动多源探测，条件触发
- [ ] ⏸ **Tauri 迁移不做**：Motrix-Next 重写成本与其「单引擎 + 轻功能面」匹配，OmniGet 多引擎/工具箱/渲染层复用耦合度不匹配；包体瘦身走引擎按需下载（#3）与零包体 JS 运行时（#16）路线
- [ ] ⏸ 维持不做（backlog §四 + #32）：图片/图集/电商批量（gallery-dl 不引入）、MIDI 导出、生成式 AI（歌词生成等）、slskd（Soulseek）、rclone、开放社区执行脚本、迅雷 SDK

## 贯穿全期的三条主线约束

1. **合规红线**：不自研签名算法（a_bogus 类）、不做任意代码执行入口、只消费自托管/公开 API——所有新平台适配沿用此边界（backlog #11/#24/#31 口径）。
2. **包体预算**：不引入新 sidecar 大二进制（mkvmerge/rclone/streamlink 均按需评估），新能力优先复用 ffmpeg / yt-dlp / N_m3u8DL-RE / aria2c 既有四件套。
3. **引擎韧性**：aria2 / yt-dlp 上游健康度列入每期发布检查项（yt-dlp 热更 + 健康面板已有；aria2 韧性评估挂六期 6.1）。
