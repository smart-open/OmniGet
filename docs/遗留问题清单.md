# OmniGet 遗留问题清单

> 记录时间：2026-09-30。来源：跨平台全面审查（22 项发现，14 项已修复）与本轮迭代遗留。
> 约定：`🔴 高 / 🟠 中 / 🟡 低`；修复后在条目后追加 `[已修复 YYYY-MM-DD]`。

## 发布阻塞类

### 1. 🔴 sidecar 三平台生产链路空缺
- **现状**：`resources/engines/` 各平台目录为空，CI（`.github/workflows/build.yml`）三平台出包全部是"零引擎安装包"，仅 warning 不阻断。
- **原因**：PyInstaller 不支持交叉编译，`service/build_service.py` 只能在对应宿主平台产出二进制；aria2c / yt-dlp / ffmpeg 也需按平台下载或自建。
- **待办**：
  - [ ] CI 增加 sidecar 构建阶段：win / mac(arm64+x64) / linux runner 各自执行 `build_service.py`
  - [ ] 各平台 runner 下载官方预编译 aria2c / yt-dlp / ffmpeg（含 ffprobe）归档到 `resources/engines/<platform>-<arch>/`
  - [ ] sidecar 缺失时将 CI 从 warning 升级为 fail（发布门禁）
- **关联文件**：`.github/workflows/build.yml`、`service/build_service.py`

### 2. 🔴 macOS 签名与公证未配置
- **现状**：`electron-builder.yml` mac 段无 `identity` / `notarize` / hardened runtime；用户首次打开 dmg 会命中 Gatekeeper（"已损坏，无法打开"）。
- **待办**：
  - [ ] Apple Developer 账号 + 证书接入 CI（`CSC_LINK` / `CSC_KEY_PASSWORD` / `APPLE_ID` / `APPLE_APP_SPECIFIC_PASSWORD` / `APPLE_TEAM_ID`）
  - [ ] electron-builder.yml 补 notarize 配置
- **备注**：Windows 侧 `signAndEditExecutable: false`（无符号链接特权时 winCodeSign 缓存解压失败）——CI 上可开启以恢复 exe 图标/版本信息印刻，见 yml 内注释。

### 3. 🟠 publish 仓库指向确认
- **现状**：已补 `publish: provider: github`，但依赖 `package.json` 的 `repository` 字段推断仓库；未确认字段是否正确。
- **待办**：确认 `repository` 指向真实 GitHub 仓库，否则 electron-updater 拿不到 `app-update.yml` / latest 元数据。

### 4. 🟠 Linux 自动更新通道
- **现状**：electron-updater 不支持 deb 在线更新（上游限制），AppImage 支持有限。
- **待办**：Linux 通道明确"手动更新"口径（应用内检查 + 跳转下载页），或仅 AppImage 提供更新。

## 功能完善类

### 5. 🟠 BT 端口连通性诊断
- **现状**：aria2 监听 6881（TCP+UDP），无防火墙放行处理、无 NAT 提示、无连通性诊断出口。Windows 首次运行弹防火墙授权框，用户拒绝后 BT 连通性崩塌且无解释。
- **待办**：设置页/诊断页增加「BT 可连通性自检」（检测监听端口、提示放行），或首次运行引导说明。

### 6. 🟠 托盘 macOS 交互规范
- **现状**：左键 click = 切换主窗（Windows 口径）；macOS 惯例是单击弹菜单。
- **待办**：`tray.on('click')` 增加 `process.platform === 'darwin'` 分支 popUpContextMenu。

### 7. 🟡 Linux 开机自启
- **现状**：托盘菜单中 Linux 隐藏了「开机自启」项（`setLoginItemSettings` 在部分 Linux 桌面环境不可靠）。
- **待办**：评估接入 `electron-autostart` / XDG autostart 方案后放开。

### 8. 🟡 ffprobe 未纳入启动完整性校验
- **现状**：`SidecarBinary` 枚举无 `ffprobe`，`checkBinary` 不校验它；仅带 ffmpeg 不带 ffprobe 的发行包会让完整性探测静默失效（已有 try/catch 降级）。
- **待办**：枚举加入 ffprobe 并在启动自检时 warning 提示。

## 代码卫生类

### 9. 🟡 e2e 清理仍按映像名全局杀进程
- **现状**：`scripts/e2e-aria2.ts` 退出时 `taskkill /IM aria2c.exe /F`（win）或 `pkill -x aria2c`（unix），可能误杀用户机器上无关的 aria2c 实例。
- **待办**：改为按 e2e 启动实例的 PID 树终止（复用 `terminateTree` 思路）。

### 10. 🟡 `scripts/probe_formats.py` 硬编码 Windows 引擎路径
- **现状**：`resources/engines/win32-x64/yt-dlp.exe` 写死，mac/linux 开发机不可用。
- **待办**：按平台探测路径或改读环境变量 `OMNIGET_ENGINES_DIR`。

### 11. 🟡 手写路径拼接残留
- **现状**：`adapters/ytdlp.ts` 的 `join2()`（按是否含 `\` 猜分隔符）、`task/manager.ts:896` 附近 `split('/').pop()`。
- **待办**：收敛到 `path` 模块统一处理。

### 12. 🟡 sanitize 全平台按 Windows 规则清洗文件名（设计取舍，知晓项）
- **现状**：Linux/macOS 上合法文件名 `aux.txt`、末尾空格名会被改写。
- **待办**：如需平台原生口径，按 `process.platform` 差异化 `sanitizeFilename`（当前保守方案可接受）。

### 13. 🟡 工作区测试产物清理
- **现状**：仓库根目录的 `KJHDSUI21/`（下载任务测试产物目录）与 `KJHDSUI21.aria2`（已由 `*.aria2` 规则忽略）为调试残留。
- **待办**：清理目录；如常驻用于测试，加入 `.gitignore`。
